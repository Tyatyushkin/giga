Что не так: ожидаемые результаты утверждают «HTTP 200» для операции

  (шаг 1 — снимок реестра до деплоя, шаг 4 — подтверждение записи, шаг 10 — контроль после DELETE).
Почему: код ответа этой операции корпусом не задан. Проверено REQ-01…REQ-06.
  REQ-02 говорит только «топология присутствует в ответе GET …/topologies (JSON-список, каждая
  запись содержит поля name и timestamp)» — про код ответа ни слова; REQ-06 — «топология
  отсутствует в списке GET …/topologies», тоже без кода. REQ-01 явно отдаёт код наружу:
  «код ответа определяется операцией (REQ-02…REQ-06)» — то есть для GET …/topologies он
  не определён нигде. Коды, заданные корпусом, — 200 на PUT топологии (REQ-02), 200 на LISTSTATUS
  и OPEN (REQ-03, REQ-05), 201 на CREATE (REQ-04), 200 на DELETE (REQ-06), 401 при неверном пароле
  (REQ-01), 404 после удаления (REQ-06). 200 на GET …/topologies в этом перечне отсутствует.
  Ни один из одиннадцати пробелов кейса это не фиксирует, поэтому послабление «требование молчит +
  пробел объявлен» не применяется.
Исправить (любой из двух путей, второй предпочтителен):
  а) убрать «HTTP 200» из ожидаемых результатов шагов 1, 4, 10, оставив наблюдаемые, которые REQ-02
