## Отдельно: что ломается из-за смены первичного формата на JSON

1. **Структурный гейт идёт по порождённому файлу, а не по источнику.** `validate_cases.py`
   собирает `*.md` (`collect()` по `rglob("*.md")`), а JSON видит только через парность.
   Парность же сверяет `id`, число шагов и три колонки шагов — и всё. Предусловия, таблица
   данных, постусловия, пробелы и вопросы не сверяются ничем: если конвертер не запустить
   после правки этих разделов в JSON, устаревший Markdown пройдёт линтер молча. В этом
   прогоне такого нет (см. § «Результат линтера»), но дыра в гейте есть.
2. **`steps[].requirements` — поле, которое существует только в JSON.** Дизайнер его
   заполнил, конвертер его молча теряет (в §3 Markdown колонки с якорями нет), а
   docs/format.md §5 прямо запрещает его заполнять руками. Пошаговая трассируемость,
   которую я восстанавливал по тексту ожидаемых результатов, в JSON уже лежит готовой —
   и не доходит ни до одного потребителя. Это MINOR #8.
3. **Скрытый дефект `json_to_md.py`.** Функция `_field` для списков возвращает fallback
   при любом значении: `return fallback if not value else fallback`. Сейчас она не
   вызывается на списках (`requirements` идёт через `_requirements_line`), поэтому дефекта
   не видно. Как только в шапку добавят второе списочное поле, оно молча превратится
   в «—» в Markdown — а Markdown теперь единственное, что читают линтер и человек.
4. **`json_to_md.py` перезаписывает `.md` без `--dry-run` и не сообщает, изменился ли файл.**
   Это делает проверку «конвертер запускали?» разрушающей: любой прогон конвертера стирает
   улику. Здесь ответ удалось получить только потому, что линтер отработал до генерации, а
   размеры файлов совпали байт в байт. Полезная доработка: печатать `unchanged/updated`
   по каждому файлу и иметь режим `--check`, который ничего не пишет и падает при
   расхождении — тогда «расхождение = конвертер не запускали» станет проверяемым фактом.
