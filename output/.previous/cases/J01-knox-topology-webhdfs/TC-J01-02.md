# E2E тест-кейс

## Общая информация

- **ID:** TC-J01-02
- **Название:** Листинг HDFS через развёрнутую топологию с неверным паролем отсекается на data-path
- **Цель:** Подтвердить, что правило Basic-аутентификации действует и на data-path развёрнутой топологии: `GET …/gateway/demo-e2e/webhdfs/v1/tmp?op=LISTSTATUS` с неверным паролем возвращает HTTP 401 с текстом `Authentication failed`, при этом топология остаётся в реестре и продолжает обслуживать запросы с верными учётными данными
- **Приоритет:** Высокий
- **Journey:** J01-knox-topology-webhdfs
- **Вариант от:** TC-J01-00
- **Покрываемые требования:** REQ-01, REQ-02, REQ-03

## Предусловия

- Наследуются предусловия TC-J01-00 и выполнены его шаги 1–3 (точка ветвления — шаг 4 основного кейса): топология `demo-e2e` развёрнута запросом `PUT …/topologies/demo-e2e` от `admin`, её запись с полями `name` и `timestamp` присутствует в реестре, gateway-URL обслуживает запросы REQ-03…REQ-05.
- Файл `/tmp/demo-e2e.txt` ещё не записан — вариант ветвится до шага 5 основного кейса.
- Отклонение от основного пути начинается на шаге 4: тот же листинг `/tmp` отправляется с логином `admin` и неверным паролем `admin-password-wrong`.
- Клиент не хранит сессию — каждый запрос несёт собственный заголовок Basic-авторизации (REQ-01).

## Тестовые данные

| Параметр | Значение | Комментарий |
|---|---|---|
| URL листинга каталога в HDFS | `https://knox-demo.stand.local:8443/gateway/demo-e2e/webhdfs/v1/tmp?op=LISTSTATUS` | Gateway-URL развёрнутой топологии, каталог `/tmp` из примера REQ-03 (пробел 8, вопрос 1) |
| URL реестра топологий | `https://knox-demo.stand.local:8443/gateway/admin/api/v1/topologies` | Контрольный запрос шага 2 |
| Логин администратора | `admin` | REQ-01 |
| Верный пароль администратора | `admin-password` | REQ-01, используется в шагах 2 и 3 |
| Неверный пароль | `admin-password-wrong` | Строка, отсутствующая в демонстрационном LDAP |
| Имя топологии прогона | `demo-e2e` | Развёрнута до начала варианта |

## Шаги

| № | Действие пользователя | Тестовые данные | Ожидаемый результат |
|---:|---|---|---|
| 1 | Запросить листинг каталога `/tmp` через gateway-URL топологии `demo-e2e`, подставив логину `admin` неверный пароль | `https://knox-demo.stand.local:8443/gateway/demo-e2e/webhdfs/v1/tmp?op=LISTSTATUS`, `admin` / `admin-password-wrong` | HTTP 401, тело ответа содержит текст `Authentication failed` (REQ-01). ## Постусловия

- Топология `demo-e2e` остаётся развёрнутой, её запись с полями `name` и `timestamp` присутствует в реестре `GET …/admin/api/v1/topologies`.
- Файлы в HDFS не создавались, содержимое каталога `/tmp` не изменялось.
- Очистка: топологию `demo-e2e` требуется снять запросом `DELETE https://knox-demo.stand.local:8443/gateway/admin/api/v1/topologies/demo-e2e` от `admin` (шаг 8 основного кейса TC-J01-00), иначе предусловие REQ-02 для следующего прогона нарушено.

## Выявленные пробелы

- **Пробел 4.** REQ-01 определяет только неверный пароль: «Запрос с неверным паролем возвращает HTTP 401, тело ответа содержит текст `Authentication failed`». Реакция на запрос без заголовка `Authorization` и на пользователя, отсутствующего в LDAP, не определена, поэтому шаг 1 проверяет одну ветку.
- **Пробел 1.** HTTP-код ответа `GET …/topologies` требованиями не задан, поэтому шаг 2 проверяет только содержимое списка.
- **Пробел 10 (новый).** REQ-01 говорит «Запрос с неверным паролем возвращает HTTP 401», но не уточняет, отражается ли отклонённый запрос на состоянии топологии или на счётчиках шлюза. Наблюдаемым в шаге 2 остаётся только присутствие записи `demo-e2e` в реестре; никаких других последствий отказа корпус не описывает.

## Уточняющие вопросы

1. Что возвращает шлюз на запрос к data-path без заголовка `Authorization` и на запрос от отсутствующего в LDAP пользователя — тот же HTTP 401 с текстом `Authentication failed` или иной ответ? Блокирует расширение шага 1 на эти две ветки.
2. Какой HTTP-код возвращает `GET …/admin/api/v1/topologies` при верных учётных данных `admin`? Блокирует шаг 2 — сейчас в нём проверяется только тело ответа.
3. Приводит ли серия отклонённых по REQ-01 запросов к блокировке учётной записи или к иному изменению состояния шлюза? Блокирует добавление шага на повторные неудачные попытки после шага 1.
4. Какой адрес стенда подставлять вместо шаблонного хоста в адресах требований и подтверждается ли `/tmp` как каталог листинга? Блокирует все шаги варианта (пробел 8).
