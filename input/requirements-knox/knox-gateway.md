# Требования к шлюзу Apache Knox — доступ и проксирование (демонстрационный набор)

> Демонстрационный корпус для быстрого прогона фабрики: один сквозной сценарий
> «администратор разворачивает топологию — пользователь работает с данными через шлюз».
> Все наблюдаемые заданы явно: HTTP-коды, заголовки, поля JSON, строки журнала.

## Аутентификация и роли

- **REQ-01.** Любой запрос через шлюз требует Basic-аутентификации против LDAP.
  Запрос с верными учётными данными возвращает HTTP 200. Запрос с неверным логином или
  паролем возвращает HTTP 401, тело ответа содержит текст `Authentication failed`.
- **REQ-02.** В демонстрационном LDAP заведены две учётные записи: `guest` / `guest-password`
  (роль `user`) и `admin` / `admin-password` (роль `admin`). Доступ к Admin API имеет только
  роль `admin`; запрос к Admin API от `guest` возвращает HTTP 403.

## Проксирование WebHDFS

- **REQ-03.** Запросы к WebHDFS выполняются через URL вида
  `https://<хост>:8443/gateway/<имя топологии>/webhdfs/v1/<путь>`.
  Запрос `GET …/webhdfs/v1/tmp?op=LISTSTATUS` от аутентифицированного пользователя
  возвращает HTTP 200 и JSON с полем `FileStatuses`.
- **REQ-04.** Запрос `PUT …/webhdfs/v1/<путь к файлу>?op=CREATE&overwrite=true` с содержимым
  в теле создаёт файл. Ответ — HTTP 201, заголовок `Location` содержит путь созданного файла.
- **REQ-05.** Запрос `GET …/webhdfs/v1/<путь к файлу>?op=OPEN` для созданного файла возвращает
  HTTP 200 и содержимое, байт в байт совпадающее с загруженным в REQ-04.
- **REQ-06.** Обращение по gateway-URL с именем топологии, которая не развёрнута на шлюзе,
  возвращает HTTP 404 независимо от корректности учётных данных.
